# Автоматизация генерации листингов кода 
**Дата:** 2026-03-22 
**Статус:** Принято 
## Контекст 
При разработке LegacyLego требуется поддерживать актуальную документацию кода (Domain model, листинги .csproj и т.д.) в Obsidian. 
Ручное копирование кода в Markdown-файлы приводит к: 
1. Рассинхрону документации и реального кода. 
2. Большим временным затратам. 
3. Ошибкам форматирования. 

---
## Решение 
Внедрение в систему автоматической сборки документации на базе PowerShell и шаблонов. 
1. **Инструментарий:** Скрипт `tools/update-project-listing-docs.ps1 (PowerShell 7.5.5). 
2. **Шаблонизация:** Использование файла-шаблона с мета-тегами (`{{@VERSION}}`,`{{@STARTCODE}}`,`{{@ENDCODE}}` ) для отделения структуры документа от данных. 
3. **Хранение:** Скрипт и шаблоны хранятся в репозитории для обеспечения воспроизводимости на любой машине. 

---
## Последствия 
### Положительные: 
* Документация всегда соответствует актуальному состоянию кода (Source of Truth). 
* Единый стиль оформления всех листингов. 
* Возможность быстрого обновления версии проекта во всех документах одной командой. 

---
### Отрицательные / Риски:
* Зависимость от установленного в системе `eza` (решается проверкой в скрипте). 
* Необходимость запускать скрипт вручную перед коммитом (в будущем можно вынести в Git Hooks).
